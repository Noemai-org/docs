# Debt register

> **Every shortcut is registered with an owner, the risk, the removal condition and the guarding test, and none may touch a Tier 0 gate or an invariant** (REQ-OPS-004: "Any deliberate shortcut is entered in a debt register with its owner, the risk it carries, the condition that removes it, and the test or guardrail that contains it until then. No shortcut may touch a Tier 0 gate or an invariant.").

Owner: EL; reviewed in the daily rhythm and on Fridays, and attached to the release evidence bundle (plan §5, §15, §13.4). A shortcut found without an entry is treated as a defect (REQ-OPS-004). Task OPS-02 opens and reviews the register.

| DEBT-01 | **Receipt authenticity is checked only in the Controller.** The `execution_rw` role may `INSERT` into `execution_receipt` (migration `0001`) and may change `decision_grant.status`; the guard of migration `0002` checks the *shape* of a receipt's signature (non-empty key, 64 lower-case hex characters), not the HMAC, because the database holds no key (PERD §41.1). A caller with `execution_rw` that bypasses the Controller can insert a well-formed `REJECTED_STALE_VERSION` receipt, with any 64 lower-case hex value as its signature, for a `SPENT` grant that has no receipt, and then void the grant. Checked on 29 Oct 2026 against a real PostgreSQL, as `execution_rw`: the insert and the void both succeed; the same insert is refused for `trust_rw`, `outcome_rw`, `evidence_rw` and `orchestrator_rw`, for a grant that was never spent (foreign key) and as an `UPDATE` of an existing receipt (immutability); `execution_rw` cannot insert a `decision_grant`.
