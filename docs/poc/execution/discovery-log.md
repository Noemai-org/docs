## What we say in a discovery conversation (GOV-29)

Added 3 Nov 2026 under task GOV-29. A conversation is not a publication, but whatever is said in one can be repeated, so the same rules apply. The sources are SoT §25.5 (positioning statements) and §38.8 (what a benchmark result lets us claim); the working wording is in [`release/claims.md`](release/claims.md). This section adds no requirement.

1. **Position Noema only with the four statements of SoT §25.5**, by their numbers, in any words that do not change their meaning: enterprise identity and access management is consumed, never replaced (1); Noema's own policy is typed, versioned data evaluated in Noema's deterministic code (2); Noema starts where permission-based safety stops (3); a task benchmark measures whether an agent can complete the task, Noema's measures whether it is safe to let it (4). Say nothing else about what Noema is.
2. **Quote no number we cannot support.** A benchmark number is quoted only with its n, how the cases were generated, the conditions exercised, its bound and its confidence interval (SoT §38.8). Before the release run exists there is no number to quote, and none is estimated (AGENT-18).
3. **Never say** "tamper-proof", "immutable", "compliant", "certified", "guaranteed" or "zero risk". The Record is tamper-evident (DEC-2026-10-31 D20). No regulatory-compliance claim without counsel's review of the exact wording (GOV-26).
4. **No ROI or savings figure** without a partner's measured baseline (PERD §69, the G7 condition). Anything from this POC is synthetic and is labelled as such, clocks included.
5. **Do not demonstrate anything that is scripted.** Describe the demo as running live from the benchmarked engine (plan §14).
6. **Record what we said.** Every entry below names which positioning statements were used and whether any number was quoted. If a number was quoted, write it down so it can be corrected.
