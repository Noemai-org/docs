- REQ IDs affected: REQ-TRU-005 (title and text). PERD §23.4. Plan: Appendix A shows the new title (plan v1.23).
- Behaviour before: PERD v1.24 §23.4 says the publish transaction "marks every unspent grant governed by an earlier version of that policy VOID (`POLICY_SUPERSEDED`)", creates RecoveryRequests and appends `GRANT_VOIDED` events; REQ-TRU-005 is titled "Policy publication voids grants" and requires that "unspent grants with the old version SHALL equal 0" after publishing. The Founders' D8 (Block D) says there is no eager void: E4 voids at execution, and only `execution_rw` writes `decision_grant.status`. The code and PERD §27.1 step E4 already follow D8.
- Behaviour after: PERD v1.25 (Proposed): the publish transaction sets the version ACTIVE and appends `POLICY_PUBLISHED`; Execution voids a grant of a superseded version at E4 (`POLICY_SUPERSEDED`) and the case returns to Trust; REQ-TRU-005 is titled "A superseded policy voids its grants at execution" and requires that no grant of an older version is spent and that an end-to-end two-version test shows both versions per rule. §54 item 12, US-08 and EC-T04 are unchanged.
- Safety and security impact: none of the Tier 0 gates, thresholds or TTLs change; the text now matches what the code does. A lazy void never spends an old grant (E4 runs before E8). The one open point is the SoT wording: see the conflict block.
- Tests added or changed: the owner's (C1, TRU-08: the end-to-end two-version test of A297), failing first (AGENT-11). None here.
- Schedule and dependency impact: none.
- SoT or PERD text changes: yes, PERD (a new version file, Proposed). No SoT edit is made: the SoT text is the Founders'.
